Tokens are reusable bearer credentials, not single-use tokens: replay remains allowed only while purchase eligibility checks pass; a signed never-paid session is denied (`server/src/test-som-purchase.js:332`). Operator account deletion does not revoke a separately purchased book: `som_purchase` has no account FK (`server/src/schema.sql:411`), account deletion removes the account (`server/src/mobile-account.js:294`), and delivery queries the purchase rather than account identity (`server/src/som-purchase.js:413`; test `server/src/test-som-purchase.js:381`). The route now verifies the active key plus retained prior keys from the comma-separated `SOM_DOWNLOAD_PREVIOUS_SIGNING_SECRETS` setting or injected `previousSigningSecrets` (`server/src/som-purchase.js:212`, `server/src/som-purchase.js:408`). Operationally, a planned rotation must retain the old key for old links to keep working; a compromised old key should instead be removed and links reissued. With no retained key the route returns an explicit 403 recovery page, not a silent success (`server/src/som-purchase.js:409`). No environment values were changed or printed.
